Measure before optimizing

Measurement plan — five events, nothing creepier

Click and conversion measurement comes before any optimization. This page defines exactly what the site records, how it stays privacy-preserving, and how the next guide gets chosen from measured queries.

The five defined events

#EventFires whenPayload (no PII)
1page_viewAny page loadspath, referrer host (not full URL)
2guide_readVisitor scrolls ≥70% of a guide articlepath, guide slug
3affiliate_outbound_clickAny link with data-affiliate is clickedpath, link host only (link.amazon / amazon.com)
4feed_subscribe_clickAny RSS/feed link is clickedpath
5reader_capture_submitCapture form submitted with consentpath only — the email itself is NEVER logged by the tracker

Implementation: assets/js/analytics.js. Storage: localStorage key dh_events_v1 (this browser only) until an endpoint is configured. No cookies. No fingerprinting. No persistent identifier. The email address typed into the capture form is handled only by the (currently unconfigured) endpoint — never by the analytics tracker.

Self-hosted endpoint (optional, included)

GitHub Pages is static, so this site cannot accept POST requests by itself. The repository includes tools/collector.py — a stdlib-only JSONL collector you can run anywhere (a small VPS, a Raspberry Pi, a home server). To enable:

  1. Run python3 tools/collector.py --port 8787 --out events.jsonl --allow-origin https://kanlerxz87-cyber.github.io behind HTTPS (e.g. via Caddy) so the browser can reach it.
  2. Set window.DIYHOME_ENDPOINT = "https://your-host/events" in assets/js/analytics-config.js and rebuild.
  3. Events are then POSTed with navigator.sendBeacon; they contain no PII and no cookies.

Until then, analytics-config.js ships with DIYHOME_ENDPOINT = null and nothing leaves the browser. The dashboard renders this browser's local counts only.

Publishing cadence

  • One guide per week, Tuesdays, next slot 2026-11-24.
  • Every new guide is a file produced by tools/build.py: it is automatically added to sitemap.xml, feed.xml (RSS) and the guides index on rebuild — no hand-editing of those files.
  • Topic selection after 30 days of data: rank Search Console queries by impressions and choose the next question-shaped title from what people actually asked — never from instinct alone.

Google Search Console (owner action — SG-29)

  1. Go to Search Console → Add property → URL-prefix → https://kanlerxz87-cyber.github.io/DIYHOME2/.
  2. Verification options: HTML file upload (place the token file in the repo root of the published folder) or a google-site-verification meta tag added in tools/build.py's head() — do NOT invent a token; use the one Google issues for your property.
  3. Sitemaps → submit https://kanlerxz87-cyber.github.io/DIYHOME2/sitemap.xml.
  4. After 7–28 days, export Performance → Queries; the top questions become the next guides.

Exit criteria before optimization work starts

  • ≥ 30 days of page_view/guide_read data,
  • Associates Central clicks reconciled against affiliate_outbound_click (allowing for browsers blocking beacons),
  • At least one authorized first-party orders report available to seed the campaign ledger.
