Publishing standards & cadence

What gets published, how it is checked before publication, how often, and how to correct it.

Cadence

  • Weekly, Tuesdays. Next slot: 2026-11-24. One guide per slot; no batch publishing without a review pass.
  • Pipeline: question-shaped title (from measured queries once available, else editorial hypothesis labelled as such) → outline → draft → disclosure & claims check → data/guides.json → python3 tools/build.py → python3 tools/check_links.py → commit → PR → merge → Pages deploy.
  • Sitemap & feed: both are generated from guides.json on every rebuild; a new guide cannot ship without appearing in both.

Editorial rules

  1. Questions first. Guides are titled as questions a buyer would actually ask.
  2. No unverifiable specifics. If a value cannot be checked against an official source at build time, it is blank and flagged — never estimated.
  3. No ranking language. No "best", "top", "#1", "most popular" unless backed by first-party data and clearly labelled with date and source.
  4. Sponsored links marked three ways: rel="sponsored nofollow noopener", visible ↗ + "sponsored" note next to the link, and the above-the-fold disclosure strip.
  5. Amazon content rules: no Amazon images scraped into pages, no product copy quoted from listings, no prices displayed without a dated fetch (dates shown, and only from authorized access).
  6. Every page shows datePublished/dateModified and the masthead author (DIY Home Upgrades Editorial).

Review & corrections

  • Corrections policy: see About. Substantive corrections bump updated and trigger a rebuild and feed touch.
  • Compliance review each quarter: disclosure strip wording, footer disclosure, rel attributes, and the Operating Agreement's current wording (link on the verification register).
  • Flagged items are never silently closed: closing one means editing data/flagged.json with a dated note of what evidence resolved it.
